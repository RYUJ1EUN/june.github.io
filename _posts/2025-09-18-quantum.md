`31쪽`

controll이 상수인 경우

controll이 1인 CNOT 연산을 수행하면 controll은 상수이므로 변하지 않지만, target state는 1에의해 뒤바껴(NOT) 나옴

$$\alpha\left| 0 \right> + \beta\left| 1\right>,$$

$$\left| 0 \right> = \left[0 \ 1\right]^T$$

$$\alpha\left| 0 \right>\left| 0 \right> + \beta\left| 1\right>\left| 1 \right> = \alpha\left| 0 0 \right> + \beta\left| 1 1 \right>$$ 

(두 큐빗이 얽힌 상태, tensor product)

$$\alpha\left| 0 0 \right> + \beta\left| 0 1 \right> + \gamma\left| 1 0 \right> + \delta\left| 1 1 \right>$$
: 얽히지 않은 상태 

(모든 상태가 나올 수 있음, 계수의 합은 1)

$-$ 양자 상태 연산

Quantum Teleportation

얽힌 state를 전달하고 한쪽에서 관측하며 중첩 상태가 붕괴되면 반대쪽으로 간 양자의 state도 붕괴되면서 결과를 공유하게 됨

CNOT gate를 거쳐서 하나의 qubit을 상태가 얽힌 두 개의 qubit으로 만들면 두 사용자가 얽힌 state를 가진 qubit를 관측하여 디지털 값으로 나눠가질 수 있음

수신한 값을 다시 gate를 통해 디지털화하기 전 값으로 만들고, 상대의 state가 무엇인지 알 수 있음

ppt의 예제에서 측정한 결과가 00이면 보내려고 했던 값은 
$$\alpha\left| 0 \right> + \beta\left| 1 \right>$$
였던 것임을 별도의 작업 없이 알 수 있음

관측 결과가 10이면 Z연산을 수행해야 
$$\alpha\left| 0 0 \right> + \beta\left| 0 1 \right>$$
를 얻을 수 있으므로 Z 연산을 추가로 작업하여 원하는 $\psi$ 값을 얻을 수 있음

관측 결과는 $\alpha, \beta$에 의한 확률로 관측됨

양자 상태는 복사될 수 없음 (두 양자가 얽힌 상태일 때 한 쪽을 붕괴시켰는데 다른 쪽이 state가 정해지지 않은 양자로 둘 수 없음)

얽혀있는 상태를 재료 삼아서, 상태가 동시에 관측될 수 있도록 만드는 것

$$\frac{\left| 00 \right> + \left| 11 \right>}{\sqrt{2}}:$$
얽힌 두 양자 중 하나가 0으로 관측되면 다른 하나도 0, 하나가 1로 관측되면 다른 하나도 1인 경우만 존재하는 상태

3개의 양자를 얽히게 하는 예제의 Step 2에서 얽힘을 준비하고 Step 3에서 얽힘을 수행함

H gate는 얽힘이 사라진 것처럼 보이게 만들지만(가능한 state가 많아지는 것처럼 보임) 두 개의 얽힘을 유지하면서 새로운 state를 보이게 만듦….?

        - 명칭을 봤을 때, 양자 상태를 전송하는 기술이어야 할 것 같음
        - 그러나 현재 기술로는 이를 구현할 수 없고 현재는 다음과 같은 기술만 구현 가능함
    - 이점
        - 병렬 양자 컴퓨팅
            
            칩과 칩 사이의 통신은 양자 통신 채널이 필요함
            
            물리적으로 떨어져 있더라도 qubit level에서 신호를 주고받을 수 있는 기술(채널)이 존재하면 하나의 컴퓨터로 볼 수 있음
            
        - 양자 인터넷
            
            기존의 디지털 데이터 통신망을 건드리지 않고, 그 옆에 얽혀있는 양자 링크를 생성
            
            한 쌍의 얽힘 쌍을 노드와 라우터가 공유 ⇒ 논리적 양자 채널 생성 ⇒ quantum telepotation을 이용하면 통신 가능
            
            = 양자 직접 통신 (중국과 EU가 앞서고 있음)
            
- 양자 암호 통신
    - 양자 키 분배 (QKD)
        - BB84 : 가장 기본적이고 상용화가 쉬움
        - E91, BBM92, …
        - 하드웨어 기반의 방식
